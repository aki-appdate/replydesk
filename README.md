# ReplyDesk — 問い合わせ対応のAI返信アシスタント

ユーザーからの問い合わせに、**社内マニュアルだけを根拠に**AIが返信案を作り、担当者が確認してから送るWebアプリです。
ゲームアプリのメール問い合わせ対応でSV（5〜6名のチームリーダー）をしていた筆者が、現場で感じた課題をもとに作りました。設計・仕様決め・動作確認は筆者、実装は Claude Code（AIコーディングツール）です。

> デモ版です。ゲーム（「ほしぞらテイルズ」）・プレイヤー・問い合わせなどのデータはすべて架空です。ログイン不要で、誰でも試せます。返信を送っても実際にはどこにも送られません。

## 解決したい課題

| 現場の困りごと | ReplyDesk でやること |
|---|---|
| 同じような質問に毎回ゼロから返信文を書いていて、対応が遅れる | マニュアルの記事を探し、その内容だけを使ってAIが返信案を作る。担当者は確認して直すだけ |
| 担当者によって答えがばらつき、間違った約束（返金・補償など）をしてしまう | AIが根拠にした文がマニュアルに本当にあるかをコードで照合。危ない言い回しは送信前に止める |
| 返金・未成年の課金・利用停止など、担当者が判断してはいけない内容がまぎれる | 該当する問い合わせは「SVに相談」へ誘導し、担当者は送信できない |
| マニュアルにない質問が何か、SVが把握しにくい | 近い記事がなかった問い合わせを集計し、AIが「足すべき記事」を根拠の問い合わせつきで提案 |

## 主な機能

**受信箱（/inbox）**
- 未対応／SVに相談中／返信済み。未対応は急ぎのもの（課金・強い怒りなど）から並ぶ
- 「AIで返信案を作る」：分類・急ぎ度・お客さまの気持ち・要約・返信案・根拠にした文・確認したいことを表示
- 根拠にした文は、マニュアルに実在するかを照合して ✓／✗ で表示
- 「返金します」「補償します」「必ず直ります」などの言い回しを入力中に検知し、直すまで送信できない
- SVへの相談が必要な内容は、担当者からは「SVに相談する」しか押せない。SVは内容を判断して送信できる

**マニュアル（/knowledge）**
- AIに渡している記事の一覧と本文。記事ごとに、返信の根拠に使われた回数を表示

**SVダッシュボード（/insights）**
- 今日／今週／直近2週間の切り替え
- 受信数・未対応・最初の対応までの平均時間・24時間以内の対応率（24時間以上放置されている未対応も「間に合わなかった件」として数える）
- AI返信案の採用率（送った文がAI案とどれだけ同じか）と、AIを使った返信の割合
- 問い合わせの分類、よく根拠に使われた記事
- 「マニュアルに足す記事の下書き」：マニュアルにない質問から、AIが足すべき記事3つを下書きする。**下書きごとに根拠の問い合わせを文面で確かめられる**

## AIの使い方で気をつけたこと

1. **マニュアルにないことは言わせない**：AIには、問い合わせに近い記事と「返信の基本ルール」「個人情報の扱い」だけを渡します。根拠にした文は、記事の本文に実在するか（6文字以上・一字一句）をコードで照合し、確認できない文は赤で表示します。
2. **人が最後に決める**：AIの返信案は「案」です。担当者が確認して「確認したので送信する」を押すまで送りません。AI案と実際に送った文の両方を記録し、どれだけ直されたかをSV画面で振り返れます。
3. **判断してはいけないことを線引きする**：返金・未成年の課金・利用停止・法的な話は、AIの判定とは別にコードでも問い合わせの本文から検知し、担当者の送信を止めてSVへ回します（AIを使わず「自分で書く」を選んだ場合も同じです）。該当する問い合わせは受信箱で「急ぎ」として上に並びます。
4. **返答の形を固定する**：zod で定義した型から JSON Schema を作って Gemini に渡し（構造化出力）、受け取った値も同じ zod で検証します。FAQ提案では、根拠に挙げた問い合わせIDが実在するかを確かめ、根拠のない提案は捨てます。
5. **止まらない**：AIが使えないとき（未設定・無料枠の上限・通信エラー・形の不正）は、ルールベースの「見本の返答」に自動で切り替えます。画面上部の表示で、どちらが動いたか分かります。
6. **使いすぎを防ぐ**：Firebase App Check でこのサイト以外からの呼び出しを防ぎ、ブラウザごとに1日のAI利用回数を区切っています。

## 技術構成

| 分野 | 使ったもの |
|---|---|
| 画面 | Next.js 16（App Router）/ React 19 / TypeScript / Tailwind CSS 4 |
| データ保存 | Cloud Firestore（匿名認証で一人ずつ分離）。未設定時はブラウザの localStorage |
| AI | Firebase AI Logic + Gemini（Gemini Developer API の無料枠・Spark プラン） |
| セキュリティ | Firestore セキュリティルール（[firestore.rules](firestore.rules)）、App Check（reCAPTCHA v3） |
| 品質 | Vitest（単体テスト）、ESLint、GitHub Actions（push・PRで lint・型・テスト・ビルドを走らせる設定） |
| 公開 | Vercel（予定） |

```
src/
├─ app/                 画面（/ 紹介、/inbox 受信箱、/knowledge マニュアル、/insights SV）
├─ components/          画面の部品
└─ lib/
   ├─ ai/               AI呼び出し（gemini.ts）、指示文（prompts.ts）、見本の返答（sample.ts）
   ├─ store/            保存先（Firestore と localStorage を同じ窓口で切り替え）
   ├─ text.ts           記事の検索、根拠の照合、危ない言い回しの検知
   ├─ kpi.ts            SV画面の数字の計算
   ├─ knowledge.ts      架空のマニュアル（14記事）
   ├─ schemas.ts        AIの返答の型（zod）
   └─ seed.ts           架空のデモデータ
```

### 記事の探し方

問い合わせに近い記事は、記事ごとに決めた「手がかりの言葉」が問い合わせに含まれるかで選びます。
最初は文字の並びの似ている度合いだけで探していましたが、関係のない記事が上位に来ることが多かったため、現場で使われる言い回しを言葉として持たせる方式に変えました。どの記事にも当たらない問い合わせは「マニュアルにない質問」として扱います。

### データの持ち方の工夫

デモデータ（直近2週間の問い合わせ約170件と対応記録。よくある用件ほど多く届き、同じ用件でも言い方が違う）は、乱数の種を固定した関数で、いつ開いても「今日」を基準に同じものを作れます。
そのため Firestore には「お試しを始めた日時」と「利用者が送った返信・状態の変更」だけを保存し、書き込み回数を最小限にしています（無料枠で運用するため）。日付が変わると、お試しの記録はリセットされます。

## 手元で動かす

```bash
npm install
npm run dev        # http://localhost:3841
npm run check      # lint・型チェック・テスト
```

Firebase を使う場合は `.env.example` を `.env.local` にコピーして値を入れます。空のままでも、ブラウザ内保存＋見本の返答で全機能を試せます。
